## 摘要 / Summary
中文：
AF 应用栈用于在 AF 应用于产品或工作流时，保持理论、协议、应用和执行层的区分。

English:
The AF application stack keeps AF theory, protocol, application, and execution layers distinct when AF is applied to products or workflows.

## 候选规则 / Proposed Rule
中文：
AF 应用应说明当前讨论的是哪一层：理论层解释候选结构；协议层治理 A/F 保真和停机条件；应用层设计产品或工作流行为；执行层执行工具、模型和文件动作。

English:
AF applications should state which layer is being discussed: theory explains candidate structure; protocol governs A/F preservation and halt conditions; application designs product or workflow behavior; execution performs tool/model/file actions.

## 为什么重要 / Why This Matters
中文：
如果没有层级区分，AF 很容易被旧范式吸收为 UX、prompt engineering、agent planning、model routing 或 memory systems。

English:
Without layer separation, AF is easily absorbed into UX, prompt engineering, agent planning, model routing, or memory systems.

## 这不是什么 / What This Is Not
中文：
这不是产品架构强制要求，不是 agent planner 设计，也不是把 AF 降维成实现栈。

English:
This is not a product architecture mandate, not an agent-planner design, and not a reduction of AF to an implementation stack.

## 开放问题 / Open Questions
中文：
产品如何暴露协议层行为而不变成 UI 噪音？执行反馈如何返回协议层而不改写 F？

English:
How should products expose protocol-layer behavior without turning it into visible UI clutter? How should execution feedback return to protocol without rewriting F?

## 审查风险 / Review Risks
中文：
让 AF 看起来只是软件架构；把协议判断藏进产品 UX；把执行成功当成协议成功。

English:
Making AF look like software architecture only; hiding protocol decisions inside product UX; treating execution success as protocol success.
