# Zero-Curvature Baseline / 零曲率基线

Status: candidate mechanism / non-canonical
Language status: English working draft; Chinese-first rewrite required before promotion.
Source: 2026-06-06 AF self-application dialogue; raw elements 1-4, 17, 50
Layer: protocol layer; adjacent to theory layer terminology
Related existing AF sections: A/F compression; A->F identity preservation; path identity; gap halt
Summary: A candidate ideal baseline for judging deviation from compressed A->F identity, not a factual claim that the event or path has already succeeded.
Proposed rule: Zero-curvature should be treated as an ideal protocol baseline: a reference state in which A-side compaction, F-side necessity, and execution path remain aligned without substituting F. Actual work should be reviewed for curvature deviation or residual from that baseline before being treated as stable progress.
Why this matters: The baseline gives curvature language a disciplined reference point while preserving the difference between ideal alignment, observed low deviation, and actual success.
What this is not: This is not a mathematical curvature model, not a factual success label, not a guarantee of execution success, not a claim that every valid path is straight, and not a UX or prompt-writing heuristic.
Open questions: How can residual deviation be described without formulas? What evidence is enough to call a deviation low? Can future formalization introduce more precise structure without rewriting this candidate as mathematics?
Review risks: Over-formalizing curvature; treating zero curvature as achieved rather than ideal; collapsing F preservation into task completion; inventing formulas before v0.3 review.
