# Zero-Curvature Baseline / 零曲率基线

Status: candidate mechanism / non-canonical
Source: 2026-06-06 AF self-application dialogue; raw elements 1-4, 17, 50
Layer: protocol layer; adjacent to theory layer terminology
Related existing AF sections: A/F compression; A->F identity preservation; path identity; gap halt
Summary: A candidate baseline for judging whether a path preserves compressed A->F identity without substituting a smoother F'.
Proposed rule: When A and F are sufficiently compressed for the current stage, execution may proceed only as long as the selected path preserves the A->F identity and does not silently replace F with a more convenient target.
Why this matters: It gives curvature language a non-mathematical baseline: not a formula, but a protocol reference point for detecting goal drift and high-quality deviation.
What this is not: This is not a mathematical curvature model, not a guarantee of success, not a claim that every valid path is straight, and not a UX or prompt-writing heuristic.
Open questions: How can the baseline be recognized without inventing formulas? How much human confirmation is required? Can a baseline exist when A/F remains deliberately open?
Review risks: Over-formalizing curvature; treating zero curvature as perfect execution; collapsing F preservation into task completion.
