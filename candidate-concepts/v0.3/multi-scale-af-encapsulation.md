# Multi-Scale AF Encapsulation / 多尺度 AF 封装

Status: candidate mechanism / non-canonical
Source: 2026-06-06 AF self-application dialogue; raw elements 12-17, 34, 48-50
Layer: protocol layer; theory-layer adjacency
Related existing AF sections: AF as goal-unit; cross-session AF; recursive pressure testing
Summary: A candidate account of macro-AF, sub-AF, and micro-AF as possible nested goal units.
Proposed rule: AF work may be represented at multiple scales when doing so preserves goal identity, exposes gaps, and supports review; however, not every subtask or edge must become an encapsulated AF.
Why this matters: It prevents both flattening all work into one macro goal and fragmenting every action into formal protocol objects.
What this is not: This is not mandatory encapsulation, not agent task decomposition, and not a memory database schema.
Open questions: Which scale deserves a record? When should micro-AF remain informal? How should scale transitions be marked?
Review risks: Turning AF into project-management hierarchy; replacing macro-AF with sub-AF completion; confusing active graph with transcript.
