## 摘要 / Summary
中文：
多尺度 AF 封装描述 macro-AF、sub-AF 与 micro-AF 作为可能嵌套目标单元的候选关系。

English:
Multi-scale AF encapsulation describes macro-AF, sub-AF, and micro-AF as possible nested goal units.

## 候选规则 / Proposed Rule
中文：
当多尺度表示能够保护目标身份、暴露缺口并支持审查时，AF 工作可以被表示为多个尺度；但不是每个子任务或连接边都必须被封装为 AF。

English:
AF work may be represented at multiple scales when doing so preserves goal identity, exposes gaps, and supports review; however, not every subtask or edge must become an encapsulated AF.

## 为什么重要 / Why This Matters
中文：
它防止两种错误：把所有工作压平成一个 macro 目标，或者把每个动作都碎片化为正式协议对象。

English:
It prevents both flattening all work into one macro goal and fragmenting every action into formal protocol objects.

## 这不是什么 / What This Is Not
中文：
这不是强制封装，不是 agent 任务拆解，也不是记忆数据库 schema。

English:
This is not mandatory encapsulation, not agent task decomposition, and not a memory database schema.

## 开放问题 / Open Questions
中文：
哪个尺度值得记录？micro-AF 何时应保持非正式？尺度转换应如何标记？

English:
Which scale deserves a record? When should micro-AF remain informal? How should scale transitions be marked?

## 审查风险 / Review Risks
中文：
把 AF 变成项目管理层级；用 sub-AF 完成替代 macro-AF；把 active graph 混同为 transcript。

English:
Turning AF into project-management hierarchy; replacing macro-AF with sub-AF completion; confusing active graph with transcript.
