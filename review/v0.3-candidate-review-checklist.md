# v0.3 Candidate Review Checklist

Status: review scaffold / non-canonical
Source: 2026-06-06 AF self-application dialogue
Scope: candidate-concepts/v0.3 review

## Candidate Boundary

- [ ] The document explicitly says candidate / non-canonical.
- [ ] The document does not modify AF v0.1.1.
- [ ] The document does not rewrite AF v0.2.
- [ ] The document does not present candidate terminology as settled canonical terminology.
- [ ] The document preserves Chinese-first terminology or provides Chinese terminology alongside English working names.

## Layer Separation

- [ ] Theory layer is separated from protocol layer.
- [ ] Protocol layer is separated from application layer.
- [ ] Application layer is separated from execution layer.
- [ ] Execution-layer success is not treated as protocol-layer success.
- [ ] Tool, model, file, or search output is treated as evidence input, not automatic F revision.

## Curvature Discipline

- [ ] No mathematical curvature formula is invented.
- [ ] Curvature language remains a candidate protocol metaphor unless later formalized.
- [ ] Zero-curvature baseline is not treated as perfect execution.
- [ ] Curvature deviation halt is not treated as a universal refusal rule.
- [ ] Recursive certification is not treated as mathematical proof.

## Reduction Checks

- [ ] The candidate is not reduced to UX.
- [ ] The candidate is not reduced to prompt engineering.
- [ ] The candidate is not reduced to agent planning.
- [ ] The candidate is not reduced to HCI or co-creation literature.
- [ ] The candidate is not reduced to memory, retrieval, or context management.
- [ ] External research is used as adjacent evidence only, not validation of AF/AIFF.

## AF Scale Checks

- [ ] Macro-AF is not replaced by sub-AF completion.
- [ ] Sub-AF success is mapped back to macro-AF before being treated as progress.
- [ ] Micro-AF is not forced for every small action.
- [ ] Edge-to-AF recursion is not claimed for every edge case.
- [ ] The candidate does not claim every sub-AF must be encapsulated.

## Input and A/F Checks

- [ ] The candidate does not claim all user input is a task.
- [ ] A0 / natural expression is not treated as a finished prompt by default.
- [ ] Open A/F is not treated as invalid.
- [ ] Unclear A/F triggers clarification, preservation, or halt rather than automatic execution.
- [ ] F validity and A/F correspondence are distinguished.
- [ ] Path masquerading as goal is considered without dismissing the user's expressed concern.

## Governance Checks

- [ ] Candidate material is traceable to raw evidence or notes.
- [ ] Public wording avoids overclaiming around AGI, civilization transition, or human elevation.
- [ ] Private/future-safety material is not promoted into public strong clauses prematurely.
- [ ] Review risks are listed before any promotion to spec.
- [ ] Promotion requires explicit review rather than passive accumulation.
