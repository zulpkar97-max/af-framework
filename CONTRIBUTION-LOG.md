# Contribution Log and Attribution Boundaries

Status: governance log / non-spec

## Purpose

This document records contribution categories and attribution boundaries for the Ask First (AF) Framework project. It is intended to support public repository transparency, academic review, and future university or supervisor review.

It is not a canonical AF specification and does not add new AF theory.

## Contribution Categories

| Contribution category | Attribution boundary |
|---|---|
| Original problem pressure / source discomfort | Carl |
| Core theoretical direction | Carl |
| Conceptual corrections and acceptance/rejection decisions | Carl |
| Dialogue-based reflection and draft structuring | AI-assisted, Carl-reviewed |
| Codex documentation scaffolding | Codex-assisted, Carl-reviewed |
| Protocol-layer review | Carl + AI-assisted review |
| Final responsibility | Carl |

## Raw / Candidate / Canonical Distinction

The project distinguishes between raw material, candidate material, and canonical specification text.

- Raw material may include dialogue notes, source-note extractions, case observations, draft fragments, and unresolved questions.
- Candidate material may include proposed concepts, review scaffolds, non-canonical mechanisms, and future-version notes.
- Canonical material requires explicit human review, acceptance, and repository-level promotion.

AI-assisted content must not become canonical without explicit human review. AI assistance may help structure, draft, compare, or review material, but acceptance, rejection, correction, and final responsibility remain with Carl (Zulpkar Turxun).

## Process Evidence

Public GitHub commits, pull requests, review traces, source notes, raw material pools, and candidate concept files serve as process evidence. They help show when a claim was drafted, when it remained candidate, and when a change was reviewed or accepted.

These process records do not make AI a co-author. They document assistive tooling, review boundaries, and the project's governance trail.
